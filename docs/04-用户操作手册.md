## 1. 快速上手

### 1.1 准备材料

运行系统前，请确保已准备好：

1. **产品实拍图**：3~10 张，清晰展示产品外观、颜色、材质、细节
2. **API 密钥**：联系技术团队获取已配置好的环境
3. **产品名称**：用于创建产品文件夹

### 1.2 三步出内容

```bash
# 第 1 步：将产品图放入输入目录
mkdir -p "输入目录/我的产品名"
cp ~/Desktop/产品图*.jpg "输入目录/我的产品名/"

# 第 2 步：运行系统
python 完整版入口 --limit-folder "我的产品名"

# 第 3 步：查看输出
open "输出目录/我的产品名/"
```

## 2. 输入规范

### 2.1 产品文件夹命名

- 使用有意义的产品名，如 `格纹帽子`、`夏季凉感衣-蓝色`
- 避免特殊字符：`/ \ : * ? " < > |`
- 每个产品一个独立文件夹

### 2.2 产品实拍图要求

| 要求 | 说明 | 建议 |
|------|------|------|
| 格式 | JPG、PNG、HEIC、WEBP | HEIC（iPhone 默认）已自动支持 |
| 数量 | 3~10 张 | 5~8 张最佳 |
| 清晰度 | 主体清晰、光线均匀 | 避免过度曝光或过暗 |
| 角度 | 多角度展示 | 正面、侧面、背面、细节特写 |
| 背景 | 简洁背景优先 | 避免杂乱背景干扰识别 |
| 禁忌 | 不要混入 AI 生成图 | 文件名避免含 `generated`、`screen` 等字样 |

### 2.3 推荐拍摄清单

**宠物服饰类**：
- [ ] 产品平铺正面照
- [ ] 产品平铺背面照
- [ ] 产品平铺侧面照
- [ ] 面料/细节特写
- [ ] 宠物穿戴效果图（如有）
- [ ] 包装图（如有文字/LOGO）

**宠物玩具类**：
- [ ] 产品正面照
- [ ] 产品侧面照
- [ ] 产品背面照
- [ ] 细节特写（缝线、发声结构等）
- [ ] 尺寸参照物对比照

## 3. 运行系统

### 3.1 常用命令速查

```bash
# 处理全部产品
python 完整版入口

# 只处理一个产品
python 完整版入口 --limit-folder "产品文件夹名"

# 只生成文字，不生成图片（省 API 费用）
python 完整版入口 --max-images 0

# 全部重新生成（覆盖已有文件）
python 完整版入口 --overwrite

# 从断点恢复（图片生成到一半中断了）
python 完整版入口 --start-from A_B4

# 先检查文件结构，不调用 API
python 完整版入口 --dry-run
```

### 3.2 模型线路选择

| 线路 | 适用场景 |
|------|---------|
| Google Gemini（推荐） | 文本质量好，图片内文字渲染准确 |
| 字节 Doubao | 国内访问快，成本较低 |

**切换方法**：运行不同入口即可，输入输出格式完全一致。

### 3.3 运行中的输出解读

```
2025-06-09 15:41:47 | INFO | Processing folder: 格纹帽子
2025-06-09 15:41:47 | INFO | Found 8 reference images.
2025-06-09 15:41:47 | INFO | Generating product report...
2025-06-09 15:42:15 | INFO | Saved product report
...
2025-06-09 15:45:30 | INFO | Generating image A_B1.png...
```

- `INFO` = 正常进行中
- `WARNING` = 有东西被跳过了（通常是正常的缓存复用）
- `ERROR` = 出错了，需要查看详情

## 4. 输出文件解读

### 4.1 输出目录结构

```
输出目录/
└── 产品名/
    ├── productreport.md           ← 商品画像报告
    ├── product_title.md           ← 商品标题
    ├── wing_keywords.md           ← 关键词
    ├── selling_points.md          ← 详情页卖点文案
    ├── selling_points.json        ← 卖点结构化数据
    ├── instagram.md               ← Instagram 文案
    ├── product_context.md         ← 精简产品上下文
    ├── image_prompts.json         ← 图片提示词
    ├── best_reference_images.json ← 选中的参考图
    ├── A_B1.png ~ A_B9.png        ← A 风格图片（高级商业摄影风）
    ├── B_B1.png ~ B_B9.png        ← B 风格图片（韩系生活方式场景风）
    └── run.log                    ← 运行日志
```

### 4.2 各输出文件用途

| 文件 | 用途 | 是否需人工审核 |
|------|------|--------------|
| 商品画像报告 | 了解产品画像、确认 AI 识别是否准确 | ✅ 建议审核 |
| 商品标题 | 直接复制到 Coupang 商家后台 | ✅ 必须审核 |
| 关键词 | 复制到 Wing 后台的关键词/埋词栏 | ✅ 必须审核 |
| 详情页卖点 | 详情页文案参考，可提取到图片中 | ✅ 建议审核 |
| Instagram 文案 | 直接发布到 Instagram | ✅ 建议审核 |
| 详情页图片 | 直接上传 Coupang | ✅ 必须审核 |

### 4.3 A 风格 vs B 风格

| 风格 | 特点 | 适合场景 |
|------|------|---------|
| **A 风格** | 高级商业摄影风、干净、专业、产品主体突出 | 主图、标准详情页 |
| **B 风格** | 韩系生活方式场景风、温暖、治愈、有生活感 | 场景图、社媒传播 |

**建议**：上架 Coupang 时以 A 风格为主，B 风格可作为备选或用于 Instagram。

## 5. 审核与修正

### 5.1 商品画像报告审核要点

打开商品画像报告，重点检查：

- [ ] **产品类型判断**是否准确？（服饰类 / 玩具类）
- [ ] **颜色**是否与实拍图一致？
- [ ] **材质**是否有虚构？（如未看到防水不要写防水）
- [ ] **「图片未明确」**项是否需要补充实拍图后重跑？
- [ ] **韩国本地化建议**是否符合你的品牌定位？

**如有误**：补充更清晰的实拍图 → 删除报告文件 → 重新运行。

### 5.2 标题审核要点

- [ ] 是否为**韩文**？
- [ ] 是否包含**核心品类词**？
- [ ] 长度是否适合 Coupang 显示？
- [ ] 有无夸大或绝对化词语？

### 5.3 图片审核要点

打开每张图片，检查：

- [ ] **产品颜色**是否与实拍图一致？
- [ ] **产品图案/LOGO**是否正确？
- [ ] **韩文文字**是否清晰、无乱码、无中文/英文？
- [ ] **宠物模特**是否自然、无畸形？
- [ ] **背景**是否干净、无杂物？
- [ ] **风格**是否符合韩系审美？
- [ ] 有无**价格/促销/医疗化**违规信息？

**如某张图不满意**：
1. 记录图片键名（如 `A_B3`）。
2. 删除该图片文件。
3. 运行恢复命令：`--start-from A_B3 --limit-folder "产品名"`。

## 6. 高级用法

### 6.1 自定义提示词模板

**场景**：希望生成的文案风格更活泼 / 更高端 / 更促销感。

**方法**：
1. 复制现有的提示词模板文件。
2. 修改其中的「角色设定」「风格要求」等内容。
3. 运行时指定自定义模板路径。

**注意**：不要改动模板中的占位符结构和关键指令。

### 6.2 批量处理大量产品

```bash
# 将所有产品文件夹放入输入目录
# 然后一次运行处理全部
python 完整版入口

# 建议晚上挂机运行，早上来收结果
nohup python 完整版入口 > batch.log 2>&1 &
```

**建议**：分批次处理，每批 10~20 个产品，避免 API 限流。

### 6.3 中断后恢复

**场景**：生成到一半，电脑关机 / 网络断了 / API 限流。

**恢复方法**：

```bash
# 文本阶段中断（如卖点生成到一半）
# 直接重新运行即可，已完成的文件会自动跳过
python 完整版入口 --limit-folder "产品名"

# 图片阶段中断（如生成到 A_B4 时中断）
# 使用 --start-from 从断点恢复
python 完整版入口 --limit-folder "产品名" --start-from A_B4

# 不确定生成到哪了？查看日志
tail -20 "输出目录/产品名/run.log"
```

### 6.4 只换图片风格，不重跑文本

**场景**：对文本满意，但想换一套图片风格。

**方法**：
1. 修改图片提示词模板。
2. 删除 `image_prompts.json` 和所有 `.png` 文件。
3. 重新运行。
4. 文本文件会被复用，只重新生成图片。

## 7. 常见问题

### Q1：为什么图片里的产品颜色和实拍图不一样？

AI 图像生成对颜色的精确还原存在概率性偏差。可在提示词中加强颜色约束，或选择颜色最准确的参考图，必要时手动修图。

### Q2：生成的韩文有语法错误怎么办？

LLM 的韩文能力有限，偶发语法或拼写错误。所有韩文内容**必须人工审核**后再使用，建议配备韩文母语者或专业翻译做最终校对。

### Q3：一张图生成失败了，其他图还能继续吗？

可以。系统会跳过失败的图片，继续生成下一张。你可以在日志中看到失败原因，然后单独重新生成那张图。

### Q4：可以一次处理 100 个产品吗？

可以，但不建议。API 调用量大可能触发限流，处理时间长中断风险增加。建议分批次，每批 10~20 个产品。

### Q5：API 费用大概多少？

| 项目 | 估算费用（单次） |
|------|---------------|
| 商品画像分析 | ¥0.5~1 |
| 标题 + 关键词 + 卖点 + INS | ¥1~2 |
| 单张图片生成 | ¥0.2~0.5 |
| **单产品全链路（18 张图）** | **¥5~12** |

*实际费用取决于模型选择和平台定价。*

### Q6：如何降低 API 费用？

1. 先用 `--max-images 0` 只生成文本，确认满意后再生成图片。
2. 文本阶段优先使用 Doubao 线路（成本较低）。
3. 善用断点续跑，避免重复调用。

## 8. 最佳实践

1. **实拍图质量决定输出质量**：上传清晰、多角度、光线均匀的产品图。
2. **人工审核不可省略**：AI 生成内容仅供参考，上线前必须人工审核。
3. **善用断点续跑**：长任务随时中断随时恢复，不用担心重复扣费。
4. **保留原始模板**：自定义模板前先备份原始版本。
5. **定期归档输出**：输出目录会快速增长，定期归档到外部存储。
