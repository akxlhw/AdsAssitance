# 系统架构设计

> **CoupangAds — AI 电商内容生成系统**

---

## 1. 设计原则

1. **简单可依赖**：降低部署和运维成本，单机即可运行
2. **模型无关**：Google Gemini 与字节 Doubao 双线路对等实现，未来可扩展
3. **模板驱动**：生成逻辑通过外部模板文件驱动，运营可独立调整输出风格
4. **容错优先**：单点失败不影响全局，断点续跑保障批量任务可靠性

## 3. 核心组件

### 3.1 CLI / 配置组件

负责参数解析、输入校验、全局常量定义。

**关键常量**：

| 常量 | 值 | 说明 |
|------|-----|------|
| 文本模型（Gemini） | gemini-2.5-flash | 文本生成 |
| 图像模型（Gemini） | gemini-2.5-flash-image | 图片生成 |
| 文本模型（Doubao） | doubao-seed-2-0-lite-260215 | 文本生成 |
| 图像模型（Doubao） | doubao-seedream-5-0-260128 | 图片生成 |
| 参考图长边上限 | 1536 px | 控制传输体积 |
| 生图引用参考图数 | 3 张 | 平衡精度与成本 |
| 详情页屏数 | 10 屏 | 标准详情页结构 |
| 图片比例 | 2:3 | 竖屏详情页 |

**CLI 设计原则**：
- 所有参数均有默认值
- 模板文件路径可配置，支持多模板库切换
- 支持 Dry Run 模式（只扫描不调用 API）

### 3.2 IO 组件

| 功能 | 说明 | 异常处理 |
|------|------|---------|
| 文本文件读取 | UTF-8 编码 | 文件不存在时抛出异常 |
| DOCX 文档解析 | zipfile + XML 解析纯文本 | 格式异常时抛出异常 |
| JSON 写入 | 格式化写入 | 自动创建父目录 |
| 图片文件筛选 | 按扩展名白名单 | 忽略非支持格式 |
| 参考图加载 | 打开 → 转 RGB → 缩放 | 单张失败记录警告，继续其他 |
| API 密钥读取 | 读取首行非空内容 | 空文件时抛出异常 |

### 3.3 提示词组装组件

负责将模板文本与产品上下文拼接为完整 Prompt。

**核心服务**：

| 服务 | 输入 | 输出 |
|------|------|------|
| 报告请求组装 | 报告模板文本 | 完整请求文本 |
| 标题请求组装 | 标题模板 + 商品画像 | 完整请求文本 |
| 关键词请求组装 | 关键词模板 + 画像 + 标题 | 完整请求文本 |
| 卖点请求组装 | 卖点模板 + 画像 + 标题 + 关键词 | 完整请求文本 |
| INS 请求组装 | INS 模板 + 全部前置输出 | 完整请求文本 |
| 图片提示词组装 | 风格代码 + 卖点块 + 产品上下文 | 图片生成提示词 |

**设计特点**：每个组装服务为纯函数，无副作用，便于测试。

### 3.4 解析与容错组件

负责从模型返回的非结构化文本中提取结构化数据。

| 服务 | 用途 | Fallback 策略 |
|------|------|--------------|
| JSON 提取 | 从文本中提取 JSON 对象 | 代码块匹配 → 首尾花括号查找 → 返回原文 |
| 提示词解析 | 解析图片提示词列表 | 支持字符串/字典两种格式 |
| 参考图解析 | 解析最佳参考图文件名 | 正则提取，容错处理 |
| 卖点分段 | 从卖点文本提取 B1-B9 | 多层正则 + 行号锚定 |
| 风格规则提取 | 从模板提取 A/B 风格规则 | 正则匹配风格代码块 |

### 3.5 API 适配器组件

#### Gemini 适配器

```
文本链路（对话模式）
  ├─ 创建对话会话
  ├─ 发送消息 → 商品画像
  ├─ 发送消息 → 商品标题
  ├─ 发送消息 → 关键词
  ├─ 发送消息 → 卖点
  └─ 发送消息 → INS 文案

图片生成（独立请求模式）
  └─ 独立请求（每次携带完整提示词 + 参考图）
```

**关键设计**：文本链路使用对话模式保持上下文连贯；图片生成使用独立模式确保每张请求都携带显式上下文。

#### Doubao 适配器

```
对话管理
  ├─ 手动维护消息历史列表
  ├─ 发送参考图 + 文本
  ├─ 发送文本请求
  └─ 接收模型回复

图片生成
  └─ 调用图像生成 API（Base64 编码传输）
```

### 3.6 业务主流程组件

负责按固定顺序串联各步骤，管理缓存复用。

**完整版流程状态机**：

[生成/复用 关键词]                │
  │                               │
  ▼                               │
[生成/复用 卖点] ──→ [解析 B1-B9] │
  │                               │

## 4. 数据模型

### 4.1 状态持久化

系统采用文件系统作为唯一状态存储：

```
状态 = f(输出目录文件列表, CLI 参数)
```

**状态推断规则**：

| 检查条件 | 推断状态 | 行为 |
|---------|---------|------|
| 输出文件存在 + 非强制覆盖 + 上游未变更 | COMPLETED | 跳过 |
| 输出文件不存在 | PENDING | 执行生成 |
| 强制覆盖模式 | FORCED_REGEN | 重新生成 |
| 上游文件更新于当前文件 | STALE | 重新生成 |

### 4.2 核心数据结构

**参考图对象**：
```
{
    path: 文件路径,
    filename: 文件名,
    image: PIL.Image (RGB, 长边≤1536),
    data_url: Base64 Data URL (Doubao 线路)
}
```

**卖点区块**：
```
{
    B1: "卖点标题\n卖点正文...",
    B2: "卖点标题\n卖点正文...",
    ...
    B9: "卖点标题\n卖点正文..."
}
```

**图片提示词**：
```
[
    { style: "A", screen: "B1", prompt: "...", filename: "A_B1.png" },
    ...
]
```

## 5. 扩展性设计

### 5.1 新增模型线路

1. 新建应用入口文件
2. 复用现有 IO、解析、编排逻辑
3. 实现新的 Client Adapter 封装目标平台 API
4. 保持输出文件结构和命名完全一致

### 5.2 模板扩展

- 新增品类：复制现有模板，修改 10 屏结构
- 新增市场：替换韩文要求为日文/英文，保持代码不变

### 5.3 SaaS 化演进路径

```
Phase 1: 单机 CLI（当前）
    ↓
Phase 2: 任务队列（Celery + Redis）
    - 将单产品流程包装为异步任务
    - Web 层负责上传、触发、查询
    ↓
Phase 3: 引入数据库（PostgreSQL）
    - 产品表、任务表、输出文件表
    - 替代文件系统状态推断
    ↓
Phase 4: 对象存储（S3/MinIO/OSS）
    - 参考图和生成图持久化
    - 本地仅保留临时文件
```

## 6. 技术决策

### ADR-001：单体应用 vs 微服务

**决策**：保持单体脚本架构，不拆分为服务。  
**理由**：项目无复杂依赖，包结构增加认知成本；单体便于复制、修改、运行。

### ADR-002：文件系统状态 vs 数据库状态

**决策**：用文件系统推断状态，不引入数据库。  
**理由**：单机工具场景下数据库是过度设计；文件系统天然支持查看和手动管理。

### ADR-003：明文密钥 vs 密钥管理

**决策**：密钥明文存储于单文件。  
**理由**：降低配置复杂度；已知风险为可能意外提交到 Git，需通过 `.gitignore` 规避。

### ADR-004：对话模式 vs 独立请求

**决策**：文本链路使用对话模式，图片生成使用独立请求。  
**理由**：对话模式保持上下文连贯，减少 token 消耗；独立模式确保每张图片携带完整上下文。
