# 功能规格说明书

> **CoupangAds — AI 电商内容生成系统**

---

## 1. 功能总览

系统包含 8 个核心功能模块，按执行顺序排列如下：

| 序号 | 功能模块 | 优先级 | 执行阶段 |
|------|---------|--------|---------|
| 1 | 商品画像分析 | P0 | 文本阶段 |
| 2 | 商品标题生成 | P0 | 文本阶段 |
| 3 | 关键词挖掘 | P0 | 文本阶段 |
| 4 | 详情页卖点文案 | P0 | 文本阶段 |
| 5 | 社媒文案生成 | P1 | 文本阶段 |
| 6 | 智能参考图筛选 | P0 | 图像准备阶段 |
| 7 | 图片提示词组装 | P0 | 图像准备阶段 |
| 8 | 详情页图片生成 | P0 | 图像生成阶段 |

## 2. 功能规格详述

### 2.1 商品画像分析（FR-001）

**功能描述**：基于产品实拍图，通过多模态 AI 分析生成结构化商品识别报告。

**触发条件**：每个产品处理流程的第一个步骤。

**输入**：
- 产品实拍图（3~10 张，JPG/PNG/HEIC/WEBP 格式）
- 商品画像分析提示词模板

**输出**：商品画像报告（Markdown 格式）

**报告结构（13 大章节）**：

| 章节 | 必填内容 | 格式要求 |
|------|---------|---------|
| 基础产品信息 | 产品大类、具体名称、Coupang 韩文品类词、标品/半标品/非标品判断 | 品类词必须为韩文 |
| 产品事实提取 | 颜色、材质、尺寸、结构、图案、包装、配件、可见文字/LOGO | 未确认项标注「图片未明确」 |
| 核心需求池判断 | 主需求池、次需求池、不建议进入的需求池 | 给出判断理由 |
| 需求结构表达链 | 人群/宠物对象、使用场景、具体需求、核心卖点、证据/参数、购买理由、退货风险 | 结构化输出 |
| 核心卖点提炼 | 5-8 个结构化卖点 | 每个卖点有证据支撑 |
| 韩国转化判断 | 目标用户画像、适用犬种/猫种、购买动机、价格定位、转化优势/风险 | 符合韩国市场特征 |
| 主图点击力判断 | 点击力评分（1-10）、优势、不足、建议补充图片 | 评分有理有据 |
| 详情页承接力判断 | 首屏/中段/后段建议、降低退货风险的信息 | 可执行的建议 |
| 标题与埋词种子词 | 核心品类词、细分类词、场景词、功能卖点词、材质/结构词、风格词、犬种/猫种词 | 分类清晰 |
| 新品期词库建议 | 关键词方向、否词方向、适合自动广告测试的词 | 可直接用于广告 |
| 韩国本地化视觉建议 | 推荐视觉风格、背景、宠物模特、拍摄角度、文案语气 | 符合韩系审美 |
| 合规与不确定信息 | 不得使用的卖点、图片无法确认的信息、需要补充的信息 | 风险前置 |
| 最终识别结论 | 一句话总结产品定位 | 简洁准确 |

**核心约束**：
- 所有判断必须基于图片中可见信息，不得虚构
- 未确认的属性标注「图片未明确」
- 严禁无依据断言

### 2.2 商品标题生成（FR-002）

**功能描述**：基于商品画像，生成适配 Coupang 平台的高点击率韩文标题。

**触发条件**：商品画像分析完成后。

**输入**：
- 商品画像报告
- 标题生成提示词模板

**输出**：商品标题文档（Markdown 格式）

**输出要求**：
- 标题为韩文
- 符合 Coupang 平台 SEO 规则
- 自然嵌入核心关键词，避免堆砌
- 适配韩文用户搜索习惯
- 生成 3~5 个变体供运营选择

---

### 2.3 关键词挖掘（FR-003）

**功能描述**：构建三层关键词矩阵，并提供蓝海词推荐。

**触发条件**：商品标题生成完成后。

**输入**：
- 商品画像报告
- 商品标题
- 关键词挖掘提示词模板

**输出**：关键词文档（Markdown 格式）

**输出结构**：
- 核心词（品类词）
- 属性词（材质/功能/风格）
- 长尾词（场景/人群/痛点）
- 蓝海词推荐（搜索量适中、竞争度低）
- 不建议使用的词及原因

---

### 2.4 详情页卖点文案（FR-004）

**功能描述**：按模块化结构生成详情页卖点文案。

**触发条件**：关键词挖掘完成后。

**输入**：
- 商品画像报告
- 商品标题
- 关键词
- 卖点文案提示词模板

**输出**：
- 卖点文案文档（Markdown 格式）
- 结构化卖点数据（JSON 格式，B1-B9）

**B1-B9 结构**：

| 区块 | 典型内容 | 适用屏位 |
|------|---------|---------|
| B1 | 主卖点 / 核心功能 | 第 1~2 屏 |
| B2 | 材质/工艺优势 | 第 4~5 屏 |
| B3 | 设计/外观卖点 | 第 1~3 屏 |
| B4 | 使用场景 | 第 3~4 屏 |
| B5 | 舒适度/体验 | 第 2~4 屏 |
| B6 | 安全性/品质保障 | 第 4~5 屏 |
| B7 | 尺码/适配信息 | 第 10 屏 |
| B8 | 品牌/信任背书 | 第 1~2 屏 |
| B9 | 购买提醒/售后 | 第 10 屏 |

**格式要求**：
- 采用 FAB 法则（Feature-Advantage-Benefit）
- 每个区块包含：卖点标题、韩文正文、支撑证据
- 避免夸大、虚假、医疗化、绝对化表达

### 2.5 社媒文案生成（FR-005）

**功能描述**：生成适配 Instagram 平台的种草文案。

**触发条件**：卖点文案生成完成后。

**输入**：
- 商品画像报告
- 商品标题
- 关键词
- 卖点文案
- 社媒文案提示词模板

**输出**：Instagram 文案文档（Markdown 格式）

**输出要求**：
- 视觉导向 + 简短文案
- 包含 Hashtag 组合
- 适配韩国 Instagram 用户阅读习惯
- Emoji 使用自然，不堆砌

### 2.6 智能参考图筛选（FR-006）

**功能描述**：从全部产品实拍图中选出 3 张最适合作为 AI 生图参考的图像。

**触发条件**：文本阶段全部完成后。

**输入**：全部产品实拍图

**输出**：3 张最佳参考图标识（JSON 格式文件名列表）

**筛选标准**：
- 产品主体清晰、无遮挡
- 光线均匀、色彩还原准确
- 能最好地展示产品颜色、材质、图案、结构
- 自动排除疑似 AI 生成图

---

### 2.7 图片提示词组装（FR-007）

**功能描述**：将卖点文案、风格规则、产品上下文组装为图片生成提示词。

**触发条件**：参考图筛选完成后。

**输入**：
- 风格规则（A 风格 + B 风格）
- B1-B9 结构化卖点
- 精简产品上下文
- 图片提示词模板

**输出**：图片提示词列表（JSON 格式）

**输出数量**：18 条（A 风格 × 9 个卖点 + B 风格 × 9 个卖点）

## 3. 通用功能

### 3.1 断点续跑

**描述**：长链路任务任意环节中断后，重新运行可自动恢复。

**行为**：
- 默认：已存在的输出文件自动跳过
- 强制覆盖模式：全部重新生成
- 精确恢复：图片阶段支持从指定键名恢复（如从 A_B4 恢复）
- 状态联动：上游文件变更时，下游依赖自动识别为需重建

### 3.2 双模型冗余

**描述**：支持 Google Gemini 与字节 Doubao 双线路，互为备份。

**行为**：
- 两条线路功能对等，输出格式一致
- 用户可通过选择不同入口切换线路
- 一条线路故障时，可无缝切换到另一条

### 3.3 错误处理

| 场景 | 处理策略 |
|------|---------|
| API 临时错误（429/500/502/503/504） | 自动重试，最多 3 次，间隔 2 秒 |
| 单张图片生成失败 | 记录错误，跳过继续下一张 |
| 单个产品处理失败 | 记录异常，继续处理下一个产品 |
| 图片文件读取失败 | 跳过该文件，继续处理其他 |
| 模型返回非结构化文本 | 多层 fallback：正则提取 → 文本兜底 → 本地组装 |

## 4. 界面规格

### 4.1 命令行接口

**通用参数**：

| 参数 | 默认值 | 说明 |
|------|--------|------|
| `--input-dir` | raw-material | 输入目录 |
| `--output-dir` | result | 输出目录 |
| `--api-key-file` | apikey.md / dbkey.md | API 密钥文件 |
| `--limit-folder` | — | 仅处理指定产品 |
| `--overwrite` | false | 强制覆盖 |
| `--dry-run` | false | 只扫描不调用 API |

**完整版专用参数**：

| 参数 | 默认值 | 说明 |
|------|--------|------|
| `--max-images` | — | 最大图片数量，0=仅文本 |
| `--start-from` | — | 从指定键恢复（如 A_B4） |
| `--max-retries` | 3 | API 错误重试次数 |
| `--request-delay` | 2.0 | 请求间隔（秒） |
| `--request-timeout` | 300000 | API 超时（毫秒） |

### 4.2 日志输出

- 控制台：实时输出到 stdout
- 文件：每个产品写入独立运行日志
- 格式：`YYYY-MM-DD HH:MM:SS | LEVEL | message`

## 5. 约束与假设

### 5.1 技术约束

- 当前为单机命令行工具，不支持并发处理
- 所有计算依赖云端 AI 模型 API
- 图片生成受模型 API 响应时间制约

### 5.2 业务约束

- 系统生成内容仅供参考，上线前必须人工审核
- 最终商业责任由使用者承担
- API 调用费用按实际用量计费

### 5.3 假设

- 用户上传的产品实拍图为合法拥有版权的原创图片
- 用户已阅读并同意所用 AI 模型平台的服务条款
- 网络环境可稳定访问模型 API 端点
