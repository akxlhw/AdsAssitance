# 测试与验收

> **CoupangAds — AI 电商内容生成系统**

---

## 1. 测试策略

由于系统核心逻辑严重依赖外部 LLM 和图像生成模型（非确定性系统），传统单元测试覆盖范围有限。采用**分层测试**策略：

```
┌─────────────────────────────────────────────────────────────┐
│                    端到端测试 (E2E)                          │
│  验证完整链路：输入产品图 → 输出全部内容资产                   │
│  频率：每次发布前 / 模型升级后                                │
└─────────────────────────────────────────────────────────────┘
                              ↓
┌─────────────────────────────────────────────────────────────┐
│                    集成测试 (Integration)                    │
│  验证模块组合：解析函数 + IO 工具 + 模板加载                   │
│  频率：每次代码变更                                           │
└─────────────────────────────────────────────────────────────┘
                              ↓
┌─────────────────────────────────────────────────────────────┐
│                    单元测试 (Unit)                           │
│  验证纯函数：数据解析、路径处理、状态判断                       │
│  频率：每次代码变更                                           │
└─────────────────────────────────────────────────────────────┘
```

---

## 2. 单元测试

### 2.1 可测试的纯函数

以下函数输入确定则输出确定，适合单元测试：

| 函数 | 测试场景 | 用例数 |
|------|---------|--------|
| JSON 提取 | 代码块包裹、裸 JSON、无 JSON、嵌套 JSON | 5+ |
| 提示词解析 | 字符串列表、字典列表、混合格式、空列表 | 5+ |
| 卖点分段 | 标准 Markdown、编号格式、缺失部分、乱序 | 5+ |
| 风格规则提取 | 标准 A/B 块、单风格、无风格标记 | 4+ |
| 图片键名规范化 | 大小写混合、下划线/连字符、空值 | 4+ |
| 疑似 AI 图判断 | 命中模式、未命中、大小写混合 | 4+ |
| 产品上下文组装 | 正常输入、超长输入、空输入 | 3+ |

### 2.2 单元测试框架

```python
# tests/test_parsers.py
import pytest

class TestExtractJsonObject:
    def test_fenced_json(self):
        text = '```json\n{"a": 1}\n```'
        assert extract_json_object(text) == '{"a": 1}'

    def test_bare_json(self):
        text = 'prefix {"a": 1} suffix'
        assert extract_json_object(text) == '{"a": 1}'

    def test_no_json(self):
        text = 'no json here'
        assert extract_json_object(text) == 'no json here'

class TestParsePrompts:
    def test_string_list(self):
        text = '{"prompts": ["prompt1", "prompt2"]}'
        result = parse_prompts(text)
        assert len(result) == 2

    def test_invalid_json(self):
        text = 'not json'
        result = parse_prompts(text)
        assert result == []
```

## 4. 端到端测试

### 4.1 冒烟测试

**用例 ID**：E2E-001  
**名称**：完整链路冒烟测试

**前置条件**：
- API Key 有效且余额充足
- 输入目录下有 3~5 张产品实拍图的测试产品

**执行步骤**：
1. 运行完整版入口，`--limit-folder "测试产品" --overwrite`
2. 等待全部完成

**预期结果**：
- [ ] 商品画像报告生成成功，文件大小 > 5KB
- [ ] 商品标题生成成功，内容为韩文
- [ ] 关键词生成成功
- [ ] 卖点文案和结构化 JSON 生成成功
- [ ] Instagram 文案生成成功
- [ ] A_B1~B_B9 共 18 张图片生成成功
- [ ] 运行日志中无 ERROR 级别日志（除已知可接受的单张图片失败）

### 4.2 断点续跑测试

**用例 ID**：E2E-002  
**名称**：中断后恢复测试

**执行步骤**：
1. 首次运行完整链路，记录完成时间 T1
2. 删除 A_B4 及之后的所有图片
3. 运行恢复命令，`--limit-folder "测试产品" --start-from A_B4`
4. 记录完成时间 T2

**预期结果**：
- [ ] 文本文件未被重新生成
- [ ] A_B1~A_B3 被跳过
- [ ] 从 A_B4 开始重新生成图片
- [ ] T2 显著小于 T1

### 4.3 Dry Run 测试

**用例 ID**：E2E-003  
**名称**：Dry Run 模式测试

**执行步骤**：
1. 运行 `完整版入口 --dry-run --limit-folder "测试产品"`

**预期结果**：
- [ ] 无 API 调用发生
- [ ] 控制台输出扫描到的图片列表
- [ ] 无输出文件生成

### 4.4 双线路一致性测试

**用例 ID**：E2E-004  
**名称**：Gemini 与 Doubao 输出一致性

**执行步骤**：
1. 使用 Gemini 线路运行完整链路，保存输出
2. 使用 Doubao 线路运行相同输入

**预期结果**：
- [ ] 两个线路的输出文件结构和命名完全一致
- [ ] 文本文件均为 Markdown 格式
- [ ] JSON 文件结构一致

## 5. 质量度量

### 5.1 自动化覆盖率目标

| 模块 | 目标覆盖率 | 当前状态 |
|------|-----------|---------|
| 解析函数 | ≥ 90% | 🟡 待补充 |
| IO 工具 | ≥ 80% | 🟡 待补充 |
| 提示词组装 | ≥ 60% | 🔴 未覆盖 |
| 业务主流程 | E2E 覆盖 | 🔴 手动测试 |

### 5.2 模型输出质量评估

| 评估维度 | 方法 | 频率 |
|---------|------|------|
| 商品识别准确率 | 人工抽样 10%，核对报告中的产品属性 | 每批次 |
| 韩文文案质量 | 韩文母语者审核，标记语法/表达问题 | 每批次 |
| 图片产品还原度 | 与参考图逐张对比，标记颜色/图案偏差 | 每批次 |
| 图片合规性 | 检查是否含中文/英文/价格/医疗化表达 | 每批次 |
| 整体可用率 | (通过审核的输出数 / 总输出数) × 100% | 每月统计 |

### 5.3 质量基线

| 指标 | 合格线 | 优秀线 |
|------|--------|--------|
| 商品识别准确率 | ≥ 85% | ≥ 95% |
| 韩文文案可用率 | ≥ 80% | ≥ 90% |
| 图片产品还原度 | ≥ 80% | ≥ 90% |
| 图片合规率 | 100% | 100% |
| 整体可用率 | ≥ 75% | ≥ 85% |

### 7.2 样例数据要求

测试用的产品实拍图应满足：
- 至少 3 张不同角度
- 包含常见格式（JPG、PNG、HEIC 至少各 1 张）
- 图片大小混合（<1MB 和 >5MB）
- 包含 1 张疑似 AI 生成图（用于测试过滤逻辑）
