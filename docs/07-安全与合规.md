# 安全与合规

> **CoupangAds — AI 电商内容生成系统**

---

## 1. 安全策略总览

系统处理的核心数据包括：API 密钥、产品实拍图、生成的商业内容。本章节定义数据分级、访问控制、传输安全和合规要求。

---

## 2. 数据分级

| 数据类型 | 分级 | 说明 | 存储位置 |
|---------|------|------|---------|
| API Key | 🔴 机密 | 直接控制模型 API 访问权限 | 本地文件（apikey.md / dbkey.md） |
| 产品实拍图 | 🟡 内部 | 商业敏感，涉及未上市产品 | 本地输入目录 |
| 生成内容 | 🟡 内部 | 包含产品细节、卖点策略 | 本地输出目录 |
| 提示词模板 | 🟢 公开 | 业务逻辑描述，无敏感信息 | 项目仓库 |
| 运行日志 | 🟡 内部 | 可能含 API 响应片段 | 本地日志文件 |

---

## 3. API 密钥安全

### 3.1 当前机制

- API Key 以明文存储于单文件（`apikey.md` / `dbkey.md`）
- 应用启动时读取首行非空内容
- 密钥仅用于本地 API 请求，不在任何服务端持久化

### 3.2 安全加固

**必须措施**：

```bash
# 1. 加入 .gitignore
echo "apikey.md" >> .gitignore
echo "dbkey.md" >> .gitignore

# 2. 设置文件权限（Linux/macOS）
chmod 600 apikey.md dbkey.md

# 3. 定期更换 API Key（建议每 90 天）
```

**可选增强**：

```bash
# 使用环境变量替代明文文件
export GEMINI_API_KEY="sk-xxx"
export DOUBAO_API_KEY="sk-xxx"
```

**生产环境最佳实践**：
- 使用密钥管理服务（HashiCorp Vault、AWS Secrets Manager、阿里云 KMS）
- 密钥注入通过 CI/CD Pipeline 或容器编排平台的 Secret 机制

## 4. 数据隐私

### 4.1 数据传输

| 传输方向 | 协议 | 说明 |
|---------|------|------|
| 本机 → Google Gemini API | HTTPS (TLS 1.3) | 图片和文本上传 |
| 本机 → 字节 Ark Platform | HTTPS (TLS 1.3) | 图片和文本上传 |

**注意**：产品实拍图和生成内容会被传输到第三方模型服务商的服务器进行处理。请确保：
- 已阅读并同意 Google / 字节的服务条款和隐私政策
- 不上传涉及国家秘密、个人隐私的图片

### 4.2 数据留存

| 数据 | 本地留存 | 第三方留存 |
|------|---------|-----------|
| 产品实拍图 | 用户控制 | 受第三方服务条款约束 |
| 生成内容 | 用户控制 | 通常不长期留存 |
| API 请求日志 | 无（除非自行抓包） | 受第三方服务条款约束 |

**建议**：定期清理不再需要的输入和输出目录。

## 5. 内容合规

### 5.1 韩国广告法合规

系统已在提示词模板中内置以下合规约束：

| 约束类型 | 具体规则 |
|---------|---------|
| 禁用绝对化词语 | 禁止 `최고`(最棒)、`완벽`(完美)、`100%`、`무조건`(无条件) 等 |
| 禁用医疗化表达 | 禁止 `치료`(治疗)、`항균`(抗菌)、`예방`(预防) 等无依据功效宣称 |
| 禁用价格促销 | 图片内禁止出现价格、折扣、促销信息 |
| 禁用虚假宣称 | 禁止虚构产品未具备的功能或属性 |
| 图片文字语言 | 图片内文字必须为韩文，禁止中文/英文/乱码 |

### 5.2 平台规则合规（Coupang）

| 规则 | 系统约束 | 人工确认项 |
|------|---------|-----------|
| 标题长度 | 模板提示中要求适配 Coupang 规范 | 运营人员最终确认 |
| 图片尺寸 | 强制 2:3 竖屏比例 | 上传前确认 |
| 禁止盗图 | 系统基于用户自有实拍图生成 | 确认图片来源合法 |
| 知识产权 | 不添加不存在的品牌元素 | 确认无侵权 |

### 5.3 合规免责声明

> **重要提示**：CoupangAds 系统生成的所有内容（文案、图片、关键词）**仅供参考**，不构成任何形式的法律建议或合规保证。最终上线内容必须经过人工审核，并由使用者承担全部商业和法律责任。AI 模型可能出现幻觉（Hallucination），生成不符合事实或违反法规的内容，运营人员必须做最终把关。

## 6. 代码安全

### 6.1 依赖安全

```bash
# 定期检查依赖漏洞
pip install safety
safety check

# 或使用 pip-audit
pip install pip-audit
pip-audit
```

### 6.2 输入校验

系统已对以下输入进行校验：

| 输入项 | 校验内容 | 异常处理 |
|--------|---------|---------|
| 产品文件夹 | 是否为目录 | 跳过非目录项 |
| 图片文件 | 扩展名白名单 | 忽略非支持格式 |
| API Key 文件 | 是否存在、是否非空 | 抛出异常 |
| 模板文件 | 是否存在 | 抛出异常 |
| CLI 参数 | 类型和范围 | argparse 自动校验 |

### 6.3 路径安全

- 使用 `pathlib.Path` 处理所有文件路径，避免路径遍历漏洞
- 不执行用户输入的任何路径作为代码或命令

## 7. 应急响应

### 7.1 API Key 泄露响应

| 时间 | 操作 |
|------|------|
| 发现后 5 分钟内 | 立即在模型平台控制台撤销/轮换该 API Key |
| 发现后 30 分钟内 | 检查 API 调用日志，确认是否有异常用量 |
| 发现后 1 小时内 | 生成新 Key，更新配置文件，验证系统正常运行 |
| 发现后 24 小时内 | 复盘泄露原因，加强防护措施 |

### 7.2 生成违规内容响应

| 场景 | 操作 |
|------|------|
| 发现单张图片含违规信息 | 立即下线该图片，不用于任何商业场景 |
| 发现文案含违规宣称 | 修正或弃用该文案，重新生成并加强审核 |
| 批量内容出现合规问题 | 暂停使用该批次全部内容，检查提示词模板 |
